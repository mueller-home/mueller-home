– Input-Namen: Input profile-reg-company-input, Input profile-reg-vat-input, Dropdown profile-reg-industry-select, Dropdown profile-reg-country-select, Input profile-reg-plz-input, Input profile-reg-city-input, Input profile-reg-website-input

– partner_business = Dropdown dropdown-partner-select's value
– NOCH OFFEN: TODO 4+5

Bubble-Spezifika:
– «Visible on page load» ist im Tab Interaction, nicht Visual
– Custom States auf Parent-Group, nicht auf Buttons
– Cell's container layout muss Column sein für Fill-Breite
– In Unterelementen: «Parent group's X» statt «Current cell's X»
– Rotes «Add» in Datenquellen-Popup: verschwindet beim Schliessen, kein Fehler
– Bubble-Suche kann nicht direkt durch Beziehungen navigieren. Workaround: GET-Parameter + Do a search for [Type] where unique id = URL-Parameter:first item
– Portal-Update-Regel (WICHTIG): Das Portal staffkeeping_portal.html speichert jeden Dokumentinhalt an zwei Stellen als Base64: (1) im CONTENTS-Objekt (für iframe-Anzeige) und (2) im labels-Objekt (für Titel-Anzeige). Beim Aktualisieren eines Dokuments im Portal müssen immer beide Stellen ersetzt werden. Zeile 92 = CONTENTS.datenbank, Zeile 101 = labels.datenbank. Python-Skript: Ersatz per lines[91].find('"datenbank": "') für CONTENTS und lines[100].find('"datenbank":"') für labels.
– Conditionals-Regel: Immer «Visible on page load = OFF» (default ausgeblendet) + Conditional «This element is visible» wenn Bedingung erfüllt. Nie umgekehrt — funktioniert nicht sauber in Bubble.
– Truncate bei Text: Height auf Fixed setzen → Cut off content erscheint automatisch
