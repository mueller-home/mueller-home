7. Wichtige Implementierungs-Details

Google Geocoding API (WICHTIG — ersetzt Nominatim):
API Connector: Collection «New Collection», Call «Google Geocode Address», Use as: Action.
URL: https://maps.googleapis.com/maps/api/geocode/json
Parameter: address=[address] (NOT Private!), components=[components] (NOT Private!), key=API_KEY (Private!)
Adress-Parameter im Workflow: Input PLZ's value + " " + Input Ort's value
Components-Parameter: "country:" + Dropdown Land's value's code (z.B. "country:CH")
Response-Felder (via results-Liste): Result of Step X's results:each item's geometry location lat:first item, ...geometry location lng:first item, ...formatted_address:first item
Status-Check: Result of Step X's status = "OK" (statt :count > 0)
Initialisierung: Mit Testwerten [8001 Zürich] + [country:CH] initialisieren, danach Werte zurücksetzen auf [address] + [components]. Nicht nochmals Re-initialize klicken!

Geocoding-Workflows (alle 3 umgestellt auf Google):
1. profile-reg-submit-btn (Registrierung): Geocode → Show error (status≠OK) → Sign up (status=OK) → Make changes User lat/lng/map_address (status=OK) → Go to profile (status=OK)
2. profile-complete-save-btn (Profil speichern): Geocode → Show error (status≠OK) → Make changes User (alle Felder, immer) → Make changes User lat/lng/map_address (status=OK) → Make changes Listings industry (immer)
3. my-listings-create-submit-btn (Inserat erstellen): Geocode → Show error (status≠OK) → Create Listing (status=OK) → Make changes Listing lat/lng (status=OK) → Hide popup (status=OK) → Reset inputs (status=OK)
4. my-listings-edit-submit-btn (Inserat bearbeiten): Geocode → Show error (status≠OK) → Make changes Listing (status=OK, lat/lng) → Hide popup (status=OK) → Display list (status=OK)
Fehler-Anzeige: Rotes Text-Element («Standort nicht gefunden») — initial unsichtbar, wird gezeigt wenn status≠OK. Wird ausgeblendet wenn PLZ oder Ort-Input geändert wird (separate Workflows pro Input).
PLZ/Ort Felder im Create-Popup werden mit Current User's postal_code/city vorausgefüllt.

Umkreissuche (index-Seite):
Filter-Elemente: input-filter-plz (Input, Placeholder «z.B. 8001 Zürich»), dropdown-filter-radius (Static: 10/25/50/100 km)
Custom States auf Group marketplace-filters: search_lat, search_lng, search_radius_km, search_lat_min, search_lat_max, search_lng_min, search_lng_max (alle Number)
Workflow filter-search-btn: Geocode (address=PLZ+City, components=country:Current User's country's code) → Set states (lat, lng, radius_km, lat_min/max=lat±radius/111, lng_min/max=lng±radius/111)
RG constraints (Ignore empty=ON): lat ≥ search_lat_min, lat ≤ search_lat_max, lng ≥ search_lng_min, lng ≤ search_lng_max
Eigene Inserate ausgeblendet: Constraint business is not Current User (permanent)

Karte (index-Seite, Map A):
Markers: Single · Marker Address: Current User's map_address → zentriert auf Betriebsstandort
map_address = Google's formatted_address (z.B. «8001 Zürich, Switzerland»)

Kontakt aufnehmen-Workflow (disclaimer-confirm-btn, index):
– Step 1: Create Conversation · Step 2: Create Message · Step 3: Reset · Step 4: Hide · Step 5: Navigate to messages ✓

my-listings / popup-vergeben:

– partner_business = Dropdown dropdown-partner-select's value
– NOCH OFFEN: Auswahl fehlerhaft + DB-Speicherung prüfen
– FEHLER: dropdown-partner-select «is not a possible option» (Bubble-Issue)

Bubble-Spezifika:
– «Visible on page load» ist im Tab Interaction, nicht Visual
– Custom States auf Parent-Group, nicht auf Buttons
– Custom States via Workflow «Set state» anlegen (Rechtsklick zeigt Add state nicht immer)
– Cell's container layout muss Column sein für Fill-Breite
– In Unterelementen: «Parent group's X» statt «Current cell's X»
– Rotes «Add» in Datenquellen-Popup: verschwindet beim Schliessen, kein Fehler
– Bubble-Suche kann nicht direkt durch Beziehungen navigieren
– Portal-Update-Regel (WICHTIG): Das Portal speichert jeden Dokumentinhalt als Base64 im CONTENTS-Objekt. Python-Pattern: re.search(r'"keyname": "([A-Za-z0-9+/=]+)"', portal) — Leerzeichen nach Doppelpunkt beachten!
– Conditionals-Regel: Immer «Visible on page load = OFF» + Conditional «This element is visible» wenn Bedingung erfüllt
– Flag-Emojis auf Windows Chrome nicht unterstützt — nur Text verwenden
– In Bubble Map Marker Address: nur einzelne Werte, keine Konkatenation möglich → map_address (Text) als Zwischenfeld nutzen
– RG-Zellen-Muster: Group ZusRowItem (direktes Kind der RG) → Data source = Current cell's Listing. Untergruppen mit Type=Listing erhalten Data source = Parent group's Listing
– Karte nach Login: Custom State page_loaded (yes/no) auf Group marketplace-main. «Page is loaded»-Workflow setzt State=yes. Map A: Visible on page load=OFF, Conditional: sichtbar wenn page_loaded=yes
– Handshake-Dropdown (Typ Conversation): Constraint listing = Parent group's Listing. Caption: Current option's initiator's company_name. Workflow speichert dropdown's value's initiator als partner_business
